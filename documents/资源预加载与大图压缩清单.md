# 资源预加载与大图压缩清单

更新时间：2026-06-20

## 一、已加入的预加载策略

本次已新增 `frontend/src/utils/assetPreloader.ts`，并接入 `frontend/src/App.tsx`。

当前策略：

- 固定剧情节点开始播放时，优先预加载该节点的场景背景、前几句台词使用的 CG / 背景 / 角色立绘。
- 当前台词播放时，自动预加载当前行和下一行的背景、CG、角色立绘。
- 再往后的两行资源以低优先级排队加载。
- 图片预加载并发限制为 2，避免在 7Mbps 服务器带宽下瞬间抢满网络。

这能改善“读文本时下一张图已经在后台加载”的体验，但首次遇到一张 2MB～3MB 的大图时，仍可能受服务器带宽限制。因此还需要压缩素材。

## 三、安全压缩原则

为了避免剧情引用路径失效，第一阶段建议只做“同路径替换”：

- `.webp` 文件继续保持 `.webp` 文件名。
- `.png` 文件继续保持 `.png` 文件名。
- 不要随意把 `cg05.png` 改成 `cg05.webp`，除非同时更新所有代码引用。
- 每批最多处理 10～20 张，处理完立即运行 `npm run build`。

推荐目标：

- 场景背景：500KB～900KB。
- 战斗背景 / CG：600KB～1MB。
- 角色立绘：300KB～700KB。
- 头像、图标、道具图：100KB～300KB。

## 四、推荐压缩流程

### 方案 A：使用 Squoosh / 图形工具手动压缩

适合少量关键图。

1. 先复制原图备份。
2. 用 Squoosh、Photoshop、Photopea 等工具压缩。
3. 输出时保持原文件名和原扩展名。
4. 覆盖 `frontend/public/assets` 中的原文件。
5. 运行：

```bash
cd frontend
npm run build
```

### 方案 B：命令行批量压缩 WebP

适合 `.webp` 场景图。可用 `cwebp` 或 ImageMagick。

示例思路：

```bash
cwebp -q 72 input.webp -o input.webp
```

如果担心覆盖失败，可以先输出到临时目录，对比大小和画质后再替换。

### 方案 C：PNG 图标 / 头像压缩

适合 `.png` 道具图、头像、CG。

建议优先用 `pngquant`：

```bash
pngquant --quality=70-90 --force --ext .png frontend/public/assets/icons/items/map.png
```

透明背景的角色、头像、道具图不要直接转 JPG，否则透明通道会丢失。

## 五、上线后的 Nginx 缓存建议

服务器上建议确认静态资源缓存已开启：

```nginx
location ~* \.(js|css|png|jpg|jpeg|gif|webp|svg|mp3|wav|ogg|mp4)$ {
    expires 30d;
    add_header Cache-Control "public, max-age=2592000, immutable";
    access_log off;
}
```

缓存只能解决第二次加载速度。第一次加载想变快，核心还是压缩图片体积和剧情预加载。

## 六、压缩后检查清单

每次压缩后请检查：

- `npm run build` 是否通过。
- 标题界面能否打开。
- 画廊是否能显示被压缩素材。
- 剧情中对应背景 / CG 是否能正常显示。
- 战斗背景、敌方模型、头像是否正常。
