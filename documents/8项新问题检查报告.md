### 🔴 仍有问题（2项）

#### 问题 34：前半段选择行动需参考蓝伞浅滩结构

- **文件**：`App.tsx` — `linearRecruitmentHints`、`getSuggestionsForActionPhase` 等多处
- **严重度**：中
- **分析**：

蓝伞浅滩战后结构使用 `available([...], "出口文本")` 模式（`postBlueShoalStory.ts:1172-1176`）：
```typescript
const available = (defs, leave?) => {
    const hints = defs.map(([, label]) => label);
    if (leave) hints.push(leave);  // ← 出口始终在最后
    return hints;
};
```
这确保出口选项永远不被"已完成"标记过滤掉。

但前半段主线（公会调查、降渊缆梯等）仍使用**普通数组 + `makeSuggestions` 过滤**。例如公会调查（`scriptedScenes.ts:710-715`）：
```
hints: [
  "前往回声酒馆找萨洛打听三名队友",
  "观察柜台旁的报告单",
  "说服米娜查看失踪远征队登记册",
  "检查委托火漆与公会认证",
]
```
没有显式的出口机制——所有选项平等对待，如果某个版本过滤掉"前往回声酒馆"，就坏档。

- **修复建议**：将前半段所有 `hints` 数组（公会、降渊缆梯等）统一为 `available(调查项, "出口")` 模式，确保出口选项始终存在。

#### 问题 37：背包使用云苓商店药水、角色面板数值不变

- **文件**：`InventoryPanel.tsx:308-322`
- **严重度**：🔴 **P0**（直接影响玩法）
- **根因分析**：

当前药水使用逻辑：
```typescript
const statPotion = getStatPotionEffect(item);
if (statPotion) {
    const nextValue = Number(state[statPotion.stat] ?? 10) + 2;  // ← state.str = nextValue
    onStatePatch({
        inventory: nextInventory,
        [statPotion.stat]: nextValue,  // ← 写入顶层的 str/dex 等
        ...
    });
}
```

写入路径：`GameState.str` → `GameState.dex` 等**顶层字段**。

但角色面板显示属性时的**读取路径**可能是：
- `state.player.attributes.str`（`dndClasses.ts` 的角色属性）
- `state.abilities.str`（另一套存储）

**数据写入位置和读取位置不一致**，导致：
- 右上角显示"药水生效：力量+2"
- 但角色面板读取的是另一个路径，数值没变
- 后端状态也因 patch 路径不匹配而未正确更新

- **修复建议**：统一属性读写路径。将药水效果写入 `state.player.attributes[stat]` 或角色面板读取的同一位置。
