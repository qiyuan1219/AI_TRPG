# 布洛克同伴支线交接说明-给队友

更新时间：2026-06-09

## 现在实现了什么

本次做的是第一幕同伴支线的测试闭环，入口在：

`测试 -> 同伴支线事件`

当前支线内容是“布洛克·铁锅：回声菌林的求救声”。它已经能跑完整流程：

1. 进入回声菌林支线。
2. 玩家先做开场判断，比如观察回声、协助采样、直接用火等。
3. 进入危机处理阶段，有 D20 检定、威胁、污染和布洛克信任变化。
4. 危机阶段结束后一定触发支线战斗。
5. 战斗结束后回到支线，按胜负结算信任、污染和奖励。
6. 进入和布洛克的 AI 自由对话阶段。

前端现在尽量复用主线已有视觉小说界面：人物立绘、底部文本框、行动栏、骰子动画、右上角对话日志。支线没有再单独做一套大段文字日志界面。

## 玩家能看到的效果

- 布洛克立绘会出现在画面中央。
- KP、玩家、布洛克的话会像主线一样在底部文本框逐句显示。
- 下方行动栏会显示支线选项。
- 自由对话阶段会提示“现在可以与布洛克自由交谈”，并给几个可点击填入输入框的问题。
- 右上角有当前支线状态面板，显示：
  - 当前支线同伴：布洛克·铁锅
  - 布洛克信任
  - 菌林威胁
  - 孢子污染
  - 支线奖励
- 危机结束后一定会进入支线战斗，不会因为威胁清零而直接跳到自由对话。

## 后续怎么扩展其他同伴支线

建议先继续沿用这个做法：先在测试界面做单个支线闭环，再由主线开发者统一接入第一幕主流程。

后续做凯娅、莉娅、卡夏、雷铎等同伴支线时，大致需要：

1. 在后端新增对应支线事件定义。
2. 给支线配置初始状态、开场选择、危机选择、奖励规则和自由对话提示。
3. 如果支线有战斗，给战斗页传入对应的战斗配置。
4. 前端测试页可以先复用当前布洛克支线页面结构，再抽成通用组件。
5. 等 5 个同伴支线稳定后，再由主线流程决定“第一场战斗后触发所选 2 名同行同伴的支线”。

## 主线接入建议

不建议现在就把支线硬塞进主线。更稳的流程是：

1. 先把每个同伴支线在测试界面跑通。
2. 主线开发者在第一幕主流程里记录玩家选择的 2 名同行同伴。
3. 第一场主线战斗结束后，主线根据同行同伴依次触发对应支线。
4. 支线结束后把结果写回主线状态，比如信任值、奖励标签、污染代价、关键旗标。
5. 主线继续推进到骨柱湿地、莱因、Boss 和结局。

这样做的好处是：支线开发和主线开发不会互相卡住，后续也方便替换剧情、数值和战斗。

## 关于奖励和道具

当前项目已有一个很轻量的背包记录：后端可以通过 `update_inventory` 或隐藏指令给玩家增加/移除物品名，前端角色面板会显示背包。

但目前还没有完整道具系统。也就是说，当前“暖孢浓汤、铁锅解毒丸、回声菌粉”更像支线奖励标签，还不会自动产生数值效果，也不会自动解锁剧情选项。

后续可以把这些奖励设计成：

- 数值加成：例如铁锅解毒丸让下一次抗毒或抗污染检定加值。
- 剧情选项：例如回声菌粉在骨柱湿地解锁“使用回声菌粉识别菌类痕迹”。
- 消耗品：例如暖孢浓汤恢复 HP 或降低一次污染。

这一步建议等主线接入时统一做，不要现在为了一个支线单独做复杂道具系统。

## 提交前一定注意

可以提交源码和说明文档，但不要提交这些东西：

- `backend/.env`
- 任何 API Key
- `data/game.db`
- `data/saves/slot-1.json`
- `frontend/dist`
- `frontend/node_modules/.vite`
- `logs`
- `.playwright-cli`
- 本地运行产生的缓存、日志、数据库和构建产物

推荐提交范围只包含：

- 后端支线代码
- 前端支线页面和少量适配代码
- 两份交接文档
- 已确认要保留的 `start.bat` 和 `.gitignore`

## 已验证内容

本轮做过轻量验证：

- 前端 `npm run build` 通过。
- 后端支线相关 Python 语法检查通过。
- 手动模拟过支线状态：危机威胁降到 0 后会进入 `battle_pending`，也就是会触发支线战斗。

构建时仍会出现两个旧提醒：

- `title-bg.webp` 运行时解析提醒。
- JS 包体积偏大提醒。

这两个不是支线逻辑 bug，不影响当前支线运行。
